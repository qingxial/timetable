# 排课诊断与修复

定位用户的 `qingxial/timetable` 检出目录，确认 `scripts/timetable_agent_tools.py`；接口以当前 `TOOL_SCHEMAS` 为准。读取当前请求和最新候选，核对源哈希、修正前缀与目标集合。不要从本技能的历史案例推定当前剩余数量或沿用旧名单。

## 按任务读取

- 解释为什么排不了、选择修复方法：读 [错误模式与修复决策](references/repair-patterns.md)。同一课程可同时命中多种原因，不能只复述引擎首先返回的状态。
- 构造实际调用：读 [工具配方与参数边界](references/tool-recipes.md)，再按需读仓库 `docs/Agent排课工具接口.md`。更正操作放在工具参数的 `corrections`，不是独立工具名称。
- 核对本项目已验证经验或论文实验口径：读 [2026-09-26案例与证据](references/case-2026-09-26.md)。案例有时间与范围，不作为新输入的默认配置或授权。

## 执行顺序

1. **定范围。** 用精确教学班ID去重，区分未排、已有记录但待复核、未确认业务范围、尚未指定授课周。虚班按母课汇总检查，不能把继承的母课LLXS逐个累计。
2. **并列诊断。** 先查源数据与课时守恒，再查静态教室供给，随后才查时间/占用与搜索预算。数据修正、授权规则变更、模型表达扩展、纯算法搜索分别记录；一个状态不能掩盖第二个阻塞原因。
3. **选择最小有效动作。** 用现有授权和充分证据直接执行。未知人数、学生关系、教学周或场地适用性应保留未知，不能填出一个能排进去的值。只对真正缺失且会影响下一步的事实询问用户，不重复询问已有授权。
4. **预检并保留成功。** `preview_data_corrections` 检查有修正的请求；修正只在内存生效。有种子时，失败子集用 `retry_repair_proposal`，新增范围用 `extend_repair_proposal`。保持全部种子修正为完全相同的前缀，追加修正只限这次目标；0移动续排不能用来修改已成功课程。
5. **按授权试排。** 先用既定域，确有时间阻塞再分阶段加入已授权晚间/周末，或显式提高集中授课表达上限。静态教室数为0时，增加时间或搜索预算不能创造教室。局部移动必须有明确可动集合，旧课也要完整排回。
6. **独立验收。** 比较原安排和种子成功是否按课程逐行保留；核对每周负荷、LLXS、教师责任周、已开启的班级/教室检查、容量/类型/校区/指定场地、禁排和课块。另查场地用途、人数等源条件缺失造成的“技术可排但业务不适用”，例如足球课选到室内跑廊。
7. **分层报告。** 输出逐课原问题、证据位置、实际执行的参数、前后安排、未解决条件及下一步。分别统计未排、技术候选、业务待核、可发布状态；不把ID有记录等同于完整排好。保存请求、响应、源/修正哈希、审计及校验结果。

## 不可混淆的语义

- `IF_CLASS_CONFICT=1/1.0` 表示免查，对应内部 `check_class=false`；0/空/缺省为检查，非法值不是授权。仅对用户明确授权的ID用 `set_class_conflict_check`；原已false也可审计无变化。保留源班级文字，披露不检查学生撞课；教师、教室等不随之关闭。
- “实际人数”列不证明人数已经冻结。`set_capacity` 要求有明确人数依据和冻结确认；教室真实容量不因人数修正而变。
- `redistribute_hours` 保持源LLXS和每个原教学周；`balanced_frontload` 是明确选定的候选计划，不是推导出的唯一事实。`set_one_off_week` 则是具体周已确认后的周域缩小。两者均不独立更正带 `@` 的虚班。
- `quarantine_incomplete_segments` 只隔离其余有效记录已完整满足逐周负荷和LLXS时的冗余坏行，不删除整门课，不编造缺周。
- `filter_fixed_occupancy=true` 仅用于0移动续排；释放占用的解释/优化不可先把同一占用对应的候选过滤掉。
- `search_limit`、`not_found_within_limits` 不是无解。QuickXplain的 `UNKNOWN` 保持未知；子集极小不等于最小数量。有限候选域最优不等于全局最优，解除占用标签也不证明旧课能排回。
- 本技能不授予新的发布权限。已经授权的修改无需再次确认；正式发布按用户本次任务范围执行，不能从候选工具输出自行推定发布指令。
