Agent 如何工作

Agent 不直接“拍脑袋排课”，而是调用受限工具、传入已授权参数，并把证据和模型边界保留下来。

确定范围区分失败教学班、已排但待复核、业务范围待确认与缺失教学计划。
并列诊断检查数据、课时、静态教室、时间/占用和搜索预算；一门课可有多个阻塞原因。
选择最小有效动作使用数据更正、容量假设、晚间/周末扩域、局部调课或规则包；不能越权推定事实。
调用确定性工具工具搜索完整候选，输出逐课状态、变更、哈希和验证范围。
独立验收并报告核对课时、周次、容量、类型、校区、教师/班级/教室冲突和保留的既有安排。
当前 11 个工具接口
diagnose_remaining

读取剩余课程与证据，不把搜索失败误写成无解。

propose_repair

在明确白名单与输入数据上生成候选方案。

repair_with_fallbacks

日间 → 晚间 → 周末，保留前阶段成功安排。

retry / extend

保留种子成功安排，重试失败项或显式扩展范围。

optimize_local_repair

有限邻域联合优化：先补入，再最少移动和质量代价。

explain_conflict

用三值 oracle 和 QuickXplain 给出受限模型内的冲突解释。

新增：教务规则包 / timetable-rule-pack skill

将可复用的教务决定变成可追溯输入

技术原理与安全边界

模型把容量、校区、教室类型、指定教室、教师责任周、班级冲突、禁排、教学周和课时作为可验证约束；偏好与授权放宽仅在明确参数范围内生效。

能力对应实现能说明什么不能说明什么
逐课补排repair_courses.py在有限候选域中找到满足已知资源约束的完整安排。搜索失败不等于现实无解。
最小扰动局部修复optimize_local_repair先最大化补入数，再减少原课移动和质量代价。仅是保留候选域内最优，不是全局最优。
质量—扰动前沿quality_frontier在相同成功水平下比较移动预算与时间质量。不把容量改成软约束，也非完整论文模型复现。
冲突解释explain_conflictSAT / UNSAT / UNKNOWN 三值下的子集极小冲突核。UNKNOWN 不能被解释成无解；释放占用不等于旧课已排回。
人数条件试排set_capacity_assumption明确标记“按某人数假设”的技术候选。不确认人数冻结，不更正源事实，不可直接发布。
