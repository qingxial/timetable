## 第 3 块　公式讲解：两个优化算法到底怎么求解

两个优化算法分别管「**先排谁**」和「**排到哪**」，是一套"构造式"求解，不是一次性解方程：

| 算法 | 在 CSP（约束满足）里的角色 | 通俗说 | 对应公式 |
|---|---|---|---|
| **贪心算法（MCF，最受约束优先）** | 变量排序（variable ordering） | 决定**先排哪个教学班** | Ω(c)=Σ\|Θ(c,r,π)\|，c\*=argmin Ω(c) |
| **balance 算法（LCV，近似最小约束值）** | 值排序（value ordering） | 决定这个班**放到哪个教室+哪个时段** | (r\*,a\*)=argmin[ w_ρ·ρ + w_ω·ω + w_ε·ε ] |

> 一句话定位（建议口述）：**贪心算法负责"挑人"（先排最难排的），balance 算法负责"挑位"（在不破坏可行性的前提下选最优时空）。两者嵌套构成一次完整的构造式求解。**

### ① 贪心算法（MCF）是怎么求解的——「先排最难的」

它不暴力枚举全局，而是**一个班一个班地确定下来、不回头**，靠"挑选顺序"逼近可行：

1. 维护待排集合，对每个未排教学班 c 计算它的**可行方案总数 Ω(c)**：
   遍历它能用的教室 R(c) × 满足周学时且避开禁排时段的上课天模式 Π(c)，
   累加同时通过「教室/教师/班级/时间偏好」四类冲突检查的可行时段数 \|Θ(c,r,π)\|。
2. **取 Ω(c) 最小的那个班**（资源最紧张、最难排）优先排 —— c\*=argmin Ω(c)。
3. 把 c\* 排定（具体落点交给 balance 算法），更新资源占用。
4. 回到第 1 步，对剩余班重算 Ω，直到全部尝试完。

**为什么这样能解：** 难排的班如果留到最后，紧俏资源早被无所谓的班占光，必然失败；
先排最难的，把容错留给容易的，可行率更高。代价是无最优性保证（启发式），
所以才需要后面的**变邻域调课**来补救首轮失败的班。

### ② balance 算法（LCV）是怎么求解的——「枚举全部可行落点，一趟扫描取最小」

当贪心选中 c\* 后，balance 决定它放到「哪个教室 + 哪个时段」。
求解机制就是 **argmin**：没有梯度、没有搜索树、没有迭代收敛，
本质是**穷举所有可行落点 → 每个加权打分 → 一个 for 循环比大小取最小者**。
（代码：`_select_balanced`，对应 `utils1.py:52-102`、候选收集在 `utils1.py:536-563`）

**第 1 步　枚举出"所有硬可行落点"** A(c\*)={(教室 r, 时段方案 a)}：

```
对 c* 的每个合适教室 room:             # filter_suitable_classrooms 先过容量/类型/校区/教学楼
    对 每个上课天模式 pattern:          # 满足周学时的天数组合，如 4 学时 = 连 4 节 或 2 天各 2 节
        new_check_period_availability(...)   # 逐时段检查教师/班级/教室/时间冲突
        → 返回的可行 arrangement 全部塞进 all_candidates
```

> 关键：进 `all_candidates` 的**全部是硬可行**的组合。balance 只在这个已合法的集合内排序，
> **永不破坏硬约束**——哪怕某课的候选全落在晚间，也照样排晚间（软先验只影响排序）。

**第 2 步　对每个候选打分，线性扫描维护当前最小（argmin）：**

> (r\*, a\*) = argmin over (r,a)∈A(c\*) of [ w_ρ·ρ(a) + w_ω·ω(r,c\*) + w_ε·ε(a) ]

```python
best, best_score = None, inf
for room, arrangement in all_candidates:        # 普通 for 循环，O(候选数)
    score = 0.6*ρ + 0.25*ω + 0.35*ε + 微小随机   # 微小随机量打破平分，避免新倾向
    if score < best_score:                       # 维护 argmin
        best_score, best = score, (room, arrangement)
return best
```

三项打分（每个候选现算；都是"软导向"，不破坏硬约束）：

- **ρ(a)　时段占用率**：先**一次性**把全体教室在本课教学周上的占用累加成一张 `load[天,节]`
  矩阵，再对该候选覆盖的每个 (天,节) 格子取平均。越满分越高 →
  **避开紧俏时段，给后面的课留空间**（"最小约束值" LCV 核心：选对别人限制最小的值）。
- **ω(r,c)　教室容量浪费率** = (教室座位 − 课容量) / 教室座位。越浪费分越高 →
  **best-fit，小班配小教室**，把大教室留给大课。
- **ε(a)　晚间节次占比**：候选覆盖格子里第 9 节及以后的比例，落晚间就加分 →
  **作息友好**（实测 random 纯均匀会把 21.8% 课推到晚间，此项把课优先留在日间）。

权重 (w_ρ, w_ω, w_ε) = (0.6, 0.25, 0.35)（可在 `utils1.py` 顶部配置，切换 first/random/balanced）。

**为什么这样能解：** 它在"哪个落点对全局后续约束最小"上做局部最优选择，
等价于约束满足里的 LCV 启发式 —— 既不牺牲首轮完成率，又顺手治好了周初堆积、
大教室错配、晚间堆课三个偏倚（实测见第 5 块）。

> 对比一句话：**贪心 MCF = 批内循环 argmin（选哪个班）；balance LCV = 一趟扫描 argmin（选哪个落点）**。两者都不是解方程，而是"算分数、比大小"的构造式启发式。

### 难度点（建议做成 4 个小卡片或要点）

1. **规模大**：数千教学班 × 数万时空槽，整数规划变量/约束达数万量级，精确求解不可行。
2. **跨校区**：教室与班级分布在 3 个校区，教师/班级不能在同一时段跨校区上课（含通勤间隔），
   约束密度显著高于单校区基准。
3. **多教师合上 + 不连续周次**：一个教学班可挂多名教师，且"上课周次"是 20 位 0/1 串
   （如单双周、前 8 周），时间维度被切碎，冲突判定更复杂。
4. **软约束多且并存**：偏好时间、避免排课时间、教室类型匹配、教学楼/校区偏好、

### 排课要求（硬约束 / 软约束，建议一页两栏）

**硬约束（必须满足）**
- 教室、教师、行政班级三类资源在任意 (周, 天, 节) 唯一占用，互不冲突；

- 教师只在其指定授课周次上课；
- 避开各班"避免排课时间"（如"周二 5–8 节"）。

**软约束（尽量满足，计入软满足度）**

- 作息友好（避免晚间 9–11 节、避免周初早间堆积）。

## 反馈⑤ 优化算法：目标函数 vs 求解方案（每个公式=一个优化问题，要给出"我设计了什么来解"）

老师的意思：公式只是"问题定义/目标函数"，要补上**"我用什么算法去解它"**。逐公式对照：

**公式1　总目标函数（字典序双目标）**
$$\max\big(\,|\{c:已排\}|,\ \textstyle\sum_c\sum_k \lambda_k s_k(c)\,\big)$$
- 这是什么优化问题：先最大化**完成率**、再最大化**软约束满足度**的字典序多目标优化。
- 我的求解方案：全局最优 NP-hard 不可解，故**分解为"构造 + 改进"两阶段启发式**——
  ①构造阶段用"贪心 MCF + balance 放置"尽量多排（保第一目标）；
  ②改进阶段用"变邻域调课"补救失败班（继续保第一目标）；
  ③在每步硬可行集合内由 balance 打分优化软满足度（第二目标）。

**公式2　最受约束优先 MCF（"怎么选可行方案数最少的教学班"——老师特别问的）**
$$\Omega(c)=\sum_{r\in R(c)}\sum_{\pi\in\Pi(c)}|\Theta(c,r,\pi)|,\qquad c^*=\arg\min_c \Omega(c)$$
- 这是什么优化问题：**变量排序**子问题——决定下一个排哪个班。
- 我的求解方案（具体怎么算出"方案数最少"的班）：
  1. 对每个未排班 c，先 `filter_suitable_classrooms` 得合适教室集 R(c)；
  2. 对每个上课天模式 π∈Π(c)（满足周学时、避开禁排）枚举，调 `new_check_period_availability`
     做教室/教师/班级/时间四类冲突检查，数出可行时段数 |Θ(c,r,π)|；
  3. 全部累加得 Ω(c)，即该班"还有多少种排法"；
  4. **一趟线性扫描取 Ω 最小者 c\***（资源最紧张、最难排的先排）；
  5. 排定后更新占用，下一轮对剩余班**重算 Ω**——即"批内循环 argmin"。
- 为什么这样设计：难排的留到最后必失败，先排最难的把容错留给好排的，可行率最高。

**公式3　balance 放置 LCV（值排序）**
$$(r^*,a^*)=\arg\min_{(r,a)\in A(c^*)}\big[w_\rho\rho(a)+w_\omega\omega(r,c^*)+w_\varepsilon\varepsilon(a)\big]$$
- 这是什么优化问题：**值排序**子问题——c\* 选定后放到哪个(教室,时段)。
- 我的求解方案：枚举 c\* 的**全部硬可行落点** A(c\*)，对每个落点按"时段占用率 ρ + 容量浪费率 ω
  + 晚间占比 ε"加权打分，**一趟扫描取分数最小者**（O(候选数) argmin，详见本文件第 3 块②节）。
- 只在硬可行集内排序 → 永不破坏硬约束；治好周初堆积/大教室错配/晚间堆课三偏倚。

**公式4　LLM 失败归因**　$\mathrm{LLM}(F_K,\mathcal L)\to(\text{原因},\text{建议})$
- 这不是优化问题，是**生成/解释**：对调课后残余失败集 F_K 结合日志 L 生成自然语言归因。

> 一页话术：**目标函数说"要什么"，三个 argmin 说"怎么一步步贪心地构造出可行解"，
> 变邻域调课说"失败了怎么补救"。**

## 反馈⑥-b　两个实验的"难度"与具体约束条件

**难度量化（某高校）：**
- 决策规模：4670 班，每班候选 = 合适教室(数十~上百) × 可行时段，单班候选可达数百~上千；
- 时空格子 547 教室 × 77 时段/周 × 18 教学周 ≈ **75 万**资源单元；
- 跨 **3 校区**（教室/班级分属南/北/郑州，不可跨校区同时占用）→ 约束密度高于单校区基准；
- **周次不连续**（20 位 0/1 串，单双周/前后段）+ **多教师合上**（一个班可挂多名教师，各自责任周）
  → 时间维度被切碎，冲突判定更复杂；
- 若建整数规划：变量/约束达数万~百万量级，**精确求解在可接受时间内不可行** → 必须启发式。

**具体约束条件（从代码冲突检查/拒绝类型实测，可直接列页）**

硬约束（违反即候选被拒，对应代码 `reject_stats`）：
1. **资源唯一占用**：教室 / 教师 / 行政班级在每个 (教学周, 天, 节) 不冲突
   （`classroom_occupied / teacher_occupied / class_occupied`）；
2. **教室容量** ≥ 课容量（SKZWS ≥ KRL）；
3. **同校区**：教室校区 = 教学班上课校区（不跨校区）；
4. **避免排课时间**：不与"避免时段"重叠（`unavailable_overlap`）；
5. **连续节次合法**：课从奇数节起（步长 2，不从偶数节开始）、连续 h 节、
   不跨午休/晚间分段边界（上午 1–4 / 下午 5–8 / 晚上 9–11，`segment_boundary`），且 s+h−1 ≤ 11；
6. **教师责任周**：教师只在其授课周次授课、占用；
7. **周学时匹配**：上课天模式总学时 = 教学班周学时 z_c；
8. **指定教室/历史教室/类型/教学楼**：若教学班指定了 JASDM/历史教室/教室类型/教学楼，必须匹配。

软约束（影响 balance 排序，非强制）：
- 偏好上课时间（`outside_pref_window`）、时段占用率 ρ、容量浪费率 ω、晚间惩罚 ε、历史教室倾向。

## 亮点一　成功率（高且可补救、失败可解释）

| 数据集 | 首轮完成率 | 调课后完成率 | 失败班 |
|---|---|---|---|
| 西交大 4000+ 班 | ★待填 | **99.1%** | 36 |
| 某高校 4670 班 | 88.44% | **98.09%** | 89 |

- 头牌数字：**99.1% / 98.09%**（两所高校均达到）。
- 调课增益：变邻域调课把某高校从 88.44%→98.09%，**净增 9.65pp**，调课成功率 83.52%（451/540）。
- 差异化卖点：**不止"排得多"，剩余失败班 100% 给出结构化归因**（教师缺失/无合适教室/教师时间窗占满三类）——
  比"只给一个完成率数字"的传统系统更可信、可解释。
- 一句话：**"高完成率 + 可补救 + 失败可解释"，三位一体。**

## 亮点二　时间（人工数周 → 小时级；让万级规模"可解"）

⚠️ **先纠错**：现 PPT/HTML 写的"≤3h"与日志不符，务必改。日志实测（4670 班，logs/）：

| 阶段 | 实测耗时 | 平均每班 |
|---|---|---|
| 首轮排课（balanced） | **4.90 h**（17654 s） | 4.27 s |
| 首轮排课（first / random 参考） | 4.17 h / 4.18 h | 3.66 / 3.64 s |
| 变邻域调课 | **18 分 46 秒** | — |
| **合计（balanced 全流程）** | **≈ 5.1 h** | — |

时间这条**别强调"绝对秒级快"**（万级规模就是要几小时），要强调**两个相对优势**：

1. **相对人工**：人工排课一轮耗时**数周**且易错 → 本方法**小时级（约 5 h）全自动**完成万级排课。
2. **相对精确解**：整数规划在万级规模上**不可行**（文献 Daskalaki：仅 92 门课就需 95 分钟，
   呈指数爆炸）→ 启发式贪心让**万级规模首次变得可解**，平均每班仅约 4 秒。
3. **调课性价比**：仅 **18 分 46 秒**就把完成率拉高近 10 个百分点。

- 一句话：**"把人工数周压缩到小时级，让整数规划做不动的万级规模变得可解。"**

## 亮点三　可泛化性（已验证 + 方法层可迁移）

把"可泛化性"拆成**已有硬证据**和**下一步规划**两层讲，避免过度宣称：

**现有证据（可直接讲）：**
- **跨院校**：已在 **2 所不同高校**真实数据上端到端验证，均达 98–99% 完成率；
- **跨校区/异构**：单数据集即含 **3 校区、33 类课程、547 间 10 种类型教室**、
  多教师合上、不连续周次等异构约束，非玩具数据；
- **方法层可配置**：流水线模块化，放置策略 first/random/balanced **一键切换**、
  规则版/LLM 版可切换、支持断点续算 → 换学校/学期只需替换数据表即可跑（见 data-convert 流程）。

**下一步强化（放"工作计划"，作为泛化性的进一步论证）：**
- 接入 **ITC-2007 / ITC-2019 国际标准基准**，在公认难度数据上论证普适性；
- 方法底层逻辑可迁移至**医护排班、考场编排、生产调度**等同类约束优化问题。

- 一句话：**"换学校只换数据、不改算法；已验证 2 所高校，下一步上国际基准。"**
