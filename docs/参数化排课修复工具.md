# 参数化排课修复工具

`scripts/repair_courses.py` 从现有 Excel 课表重建已知资源占用，诊断未排课程，在明确允许的偏好内尝试完整补排或少量挪课。输出为可审计的候选方案，不覆盖 Excel，不调用 LLM，也不消耗模型 API。

## 运行

使用 Python 3.10+ 及项目已有的 `pandas`、`openpyxl`。从仓库根目录运行：

```bash
# 严格约束基线
python scripts/repair_courses.py --output-dir repair-runs/strict-001

# 明确允许调整普通偏好，特殊要求仍保留
python scripts/repair_courses.py \
  --config configs/repair-conservative.json \
  --output-dir repair-runs/conservative-001
```

每次选择新的输出目录，避免覆盖先前审计证据。默认读取：

- `智能排课基础数据/提取的基础数据表_converted/课程表_split_merged.xlsx`
- 同目录 `教室表.xlsx`（若同目录存在班级表，也用于班级标识覆盖检查）
- `排课结果/调课后的整体结果_特殊放宽.xlsx`
- `排课结果/调课失败的排课失败课程_特殊放宽后.xlsx`

路径均可通过 `--course-file`、`--room-file`、`--schedule-file`、`--failed-file` 替换。源文件不会修改。主结果 `proposal.json` 包含输入 SHA-256、实际参数、诊断、前后安排、放宽项、完整候选课表和增量校验；`diagnosis.csv` 便于人工筛选。

## 关键参数

JSON 不认识的字段或不支持的放宽项会报错。

| 参数 | 含义 |
|---|---|
| `target_ids` | 只处理这些完整教学班 ID；空列表表示失败清单全部 |
| `allowed_changes` | 仅支持 `time_preference`、`building_preference`、`historical_room` |
| `time_scope` | `strict` 保持偏好；`same_day` 只在原偏好日换节次；`weekdays` 可换工作日 |
| `reviewed_soft_time_ids` | 已明确审核为可调整的学院指定时段课程；须同时允许 `time_preference` 才会生效 |
| `locked_ids` | 禁止改动的课程 |
| `movable_ids` | 允许移动的已排课程白名单；默认空，不动原课表 |
| `max_moved_courses` | 整个批次最多移动的原课程数，0–3，默认 0 |
| `max_candidates_per_course` | 每课的时间模式/教室候选上限；达到上限会标记截断 |
| `max_search_nodes` | 整个批次候选检查数上限 |
| `time_limit_seconds` | 搜索及候选生成的墙钟预算，不含读取工作簿 |
| `days`、`periods` | 可搜索日（0=周一至6=周日）与节次（1–11）；默认工作日1–8节 |
| `additional_forbidden` | 追加禁排窗口；不能解除固定的周二5–8节校级禁排 |

不提供放宽容量、校区、必要类型、指定教室、教师/班级冲突、课时或教学周的开关。原数据中允许共占教室/不查班级的开关原样保留，工具不会新增豁免。类型名称只代表当前数据表达的设备要求；没有设备明细时不能声称验证了未提供的设备条件。

特殊要求采用保守规则：可识别且与结构化偏好一致的“学院：…；时间：周Xn.m”遵守原时间，只有进入 `reviewed_soft_time_ids` 才可调整时间。其他自由文本要求返回 `unreviewed_special_requirement`，不让语言模型自行忽略。

## 作为 Python tool 调用

```python
from scripts.repair_data import load_dataset
from scripts.repair_courses import repair

data = load_dataset(course_path, room_path, schedule_path)
result = repair(data, target_ids=["你的教学班ID"], config={
    "allowed_changes": ["time_preference"],
    "time_scope": "same_day",
    "max_moved_courses": 1,
    "movable_ids": ["审核过的可移动教学班ID"],
    "time_limit_seconds": 60
})
```

函数返回普通 JSON 可序列化字典，不修改传入数据。Agent 负责选择已授权的参数、读取证据和解释结果；候选构造、冲突判断、课时校验与回滚由确定性代码负责。

## 算法与边界

先尝试不移动原课程的完整插入，再尝试最多3门直接阻塞课程的局部重放。每次邻域尝试都暂存原安排，所有被挪出的课完整排回才接受；任何失败均恢复。它是有界启发式修复器，不是全局最优求解器，也不是完整的多层冲突链或 CP-SAT。

当前支持每周1–8个整数课时及已明确提供的连排模板。小数周学时、源 `LLXS` 与周学时×周数不一致、未知班级标识、方括号绑定组偏好等会单独报告，不靠取整或丢失组耦合关系补齐。2节格起点沿用原引擎的1、3、5、7、9、11；没有候选不等于现实中不允许6–7节，只说明当前网格/规则下无候选。

多教师责任周逐行合并，再与教学周相交；课表每行使用自己的周次、教室和节次。班级匹配使用完整名称，不使用“班级数达到8就免查”的旧启发式。全校/全院等泛指不能证明学生不撞课，需要选课或班级映射数据。

明确的零小时倒置节次行只保留为导出警告，不产生占用；非零课程的缺失周次/无效时段则保守冻结该课程已知资源在教学周内的全部时段。已有课表冲突和未知学生关系仍会列出，因此 `validation.new_conflicts=0` 只证明本次修改对已知资源没有新增冲突，不能证明历史课表整体正确。

`not_found_within_limits` 和 `search_limit` 都不是无解证明。增加预算、更正数据或改用精确邻域求解可能改善结果。每门单独可排也不能直接相加，本工具在同一占用状态上联合试排并验证整个新增批次。
