# 剩余课程诊断与补排实验

分析日期：2026-09-25。输入来自 `main` 的 `c333a0a` 版本，读取工作簿后做增量试排，没有覆盖原始表格或发布正式课表。

## 结论

剩余课程并非全部“算法已经无能为力”。有明确的时段要求冲突、人数口径和导出代码问题。保持人数上限、校区、教室类型、教学周、规定课时、教师与已知班级冲突规则不变，在**允许调整指定学院时段**的条件场景中，本工具找到 **88 门联合补排、0 门原课程移动**的方案。学院时段是否可以作为软要求仍需业务确认，不能把这个条件场景称作原要求下已完成排课。

按冻结的实际人数选教室可为另25门恢复静态教室候选，但这些课程尚未进行人数更正后的联合补排，不能与88直接相加宣称113门成功。原始表未证明人数已经冻结，本次没有修改人数。

## 数据口径与旧诊断修正

最终课表 `排课结果/调课后的整体结果_特殊放宽.xlsx` 有8737行、4504个精确教学班ID。失败清单有162个ID，另340个按规则跳过，三组不重叠，覆盖5006个输入ID。5006包含虚班，折回原始教学班是4980；4504折回原班是4479。多教师行和多时间段不能重复计算成功课程数。

| 原类别 | 数量 | 本次复核 | 可采取的措施 |
|---|---:|---|---|
| P2 | 87 | 69门偏好6–7节跨原引擎2节格；16门偏好窗口装不下课时；2门偏好日同时被禁排 | 审核学院时段是否能调整；高学时课需增加可用天或经审核调整连排结构；不可直接忽略禁排 |
| T1 | 40 | 固定当前课表下的教师占用阻塞；21门还有学院时段要求 | 先查具体阻塞课程，再尝试有限移动或允许范围内错峰；不能据此证明全局无解 |
| R0 | 35 | 24门人数上限超过本校区全部教室容量；另11门容量和类型组合无候选 | 核对人数口径、类型和资源；移动已排课程无法创造不存在的教室 |

87门P2全部具有非空学院要求，不能默认都是普通软偏好。现有分类脚本把“有偏好但零候选”笼统标成P2；工作簿中的证据不足以支持旧文档“87门全是纯格错位、全部同日改格即可排”的断言。

35门R0均没有楼栋、指定教室或历史教室限制。单独放宽这些因素对这35门无效。类型问题包括北校区不存在所需活动桌椅类型6门、南校区对应类型容量不足5门。

## 同一基线上的联合试排

所有场景保留周二5–8节校级禁排及课程自身禁排；不更改人数、周次、冲突开关、必要类型或指定教室。搜索工作日1–8节，沿用原2节格起点。只接受完整课程的新增安排。带学院时段调整的场景是条件分析。

| 场景 | 新增完整教学班 | 移动原课程 | 仍未排 | 说明 |
|---|---:|---:|---:|---|
| 原要求，直接插入 | 0 | 0 | 162 | 只说明本次候选范围中没有成功 |
| 只调整普通偏好 | 0 | 0 | 162 | 特殊学院要求保留 |
| 原要求，最多移动3门原课程 | 0 | 0 | 162 | 达到200000次候选检查预算，非无解证明 |
| 学院指定时段可调，只在原偏好日换节次 | 73 | 0 | 89 | 需要确认这些时段属于可调整要求 |
| 学院指定时段可调，可换其他工作日 | 88 | 0 | 74 | 整批联合占用与新增冲突/完整课时校验通过 |

后两项允许调整的课程ID明确列入 `reviewed_soft_time_ids`，全部新增课程都有相应放宽记录。每门最多10000个候选、全批次200000次候选检查、60秒搜索预算。允许换工作日的场景访问62316个候选；运行时间属于本机单次观测，不能用作跨算法性能排名。

最后74门按工具首次阻塞检查分为：班级映射/覆盖问题16、总学时与周学时×周数不一致11、静态无教室20、小数周学时暂不支持5、预算与候选范围内未找到22。此分类是顺序检查结果；例如某门同时缺班级映射又无教室，会先归数据问题，所以不能把这里的20门误解为原35门中已有15门教室问题解决。

本次不移动原课程，是结果特点，不证明移动永远无益。当前局部修复实现只有直接阻塞课程重放，并非完整冲突链、ALNS或精确全局求解器。下一步应在修好数据后引入论文中的局部MIP/CP-SAT邻域，与当前有界工具做同预算比较。

## 基线课表本身需要处理的问题

1. **157个零课时尾段错误导出。** 155行“第1–0节”、2行“第3–2节”，行级周学时均0。它们所属课程的其他有效行已经满足LLXS。工具识别为不产生占用的导出占位行，保留警告，不能把整门课判为免排或未排。
2. **2行空周次。** 都属于 `15403007.001`，另一个有效段已满足36课时。本次没有猜测缺失周次，保守冻结该课程的已知资源。
3. **11门明确的分段合并代码缺陷。** `merge_special_relax.py` 保存 `(base, FA/FB)`，查询却用 `(base, @FA/@FB)`，导致回退到原整段周次。这11门最终多计128个去重课时。已修复键匹配并对缺分段周次报错，回归测试覆盖分段课时；缺少 `课程表_frac_split.xlsx` 和对应冻结状态，未重生成真实课表。
4. **课时口径尚未统一。** 对4479个原始教学班按有效周×日×节去重，与原始表LLXS对比：4018门相等、64门不足129课时、397门超出1080课时。64门不足均符合转换表 `ceil(ZXS)×周数` 口径，说明源字段之间也存在不一致，不能全部归为导出丢课时。4018只表示课时相等，不表示其他约束通过。

工具的基线资源复核还发现教师64、班级1954、教室344个冲突占用单元。这些是“资源×周×日×节”的单元数，不是冲突课程数；使用比原引擎更完整的班级标识检查，且历史导出周次问题会影响结果，需在恢复分段周次和确认班级语义后进一步核对。**新增冲突为0不意味着历史课表已整体正确。**
