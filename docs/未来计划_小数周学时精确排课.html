1.1 之前"±0.5 残差"的根源：锚点选错了

错误锚点：以 ZXS × 周数 为守恒目标。当周数为奇数时该乘积本身是半节（如 3.5×17=59.5）， 物理上不存在半节课，任何整数拆分都必然差 ±0.5——这不是拆分算法的问题，是目标本身不可达。
正确锚点：以整数的总学时 T（学时XS / 理论学时LLXS）为守恒目标。 实测 532 门课的学时XS 100% 是整数（ZXS 才是"T÷周数"算出来的派生小数）。整数目标 + 整数拆分 → 残差恒为 0。

2 · 算法：T 锚点带余除法分解（恒等式，非近似）

输入：总学时 T（整数），上课周数 N
计算：L = ⌊T / N⌋ ， r = T − L×N （即 T mod N）

分解：前 r 周每周 (L+1) 节 ＋ 后 (N−r) 周每周 L 节

守恒证明：(L+1)·r + L·(N−r) = L·N + r = T　∎（带余除法恒等式，对任意整数 T、N≥1 成立）

这正是你说的"前面几周多、后面几周少"：多的和少的只差 1 节，且总数严格等于总理论学时。

3 · 实现：复用 Issue #14 虚班机制，算法核心 0 改动

与奇数 ZXS 拆 @W/@B 完全同构，在 IO 层把一门小数课拆成两条记录：

虚班JXBID周学时上课周次 SKZCDM含义
基底班 @A原ID@AL（整数）原掩码全部 N 周每周都上的部分
增量班 @B原ID@B1（整数）原掩码的前 r 周子集只在前 r 周多上 1 节

为什么算法核心 0 改动：

  • 两条虚班都是整数 ZXS，走现有日模式生成，不再触发 ceil；
  • 共享同一教师（RWJSZCDM 同步裁剪）与班级 → 现有按周冲突检查天然保证两班不撞、也不与他人撞；
  • paired_jxbid + LCV「避同天」软约束（Issue #14 已实现）直接复用——可优先让 @B 与 @A 排在同一天相邻块或错开，策略可调；
  • 排课结果后处理 merge_virtual_jxb.py 扩展识别 @A/@B，按周次合并回一门课输出。

3.1 连排块对齐（@B 是单节，怎么落格子）

增量班 @B 是每周 1 节。两种落法，建议做成开关：
方案甲（默认）：@B 直接按单节排（现有 ZXS=1 模式已支持，结果里已有"第3-3节"这类单节先例）；
方案乙（更整齐）：r 为偶数时把 @B 改写成"隔周 2 节"（周次掩码取前 r 周的奇数位），凑满 2 节标准块， 教室利用更整齐——代价是"前段每周多1节"变成"前段隔周多2节"，总学时仍严格 = T。
